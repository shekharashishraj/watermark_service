How the synthetic walkthrough harness works

The harness builds an apartment, scans it once as a "before" visit, changes it, and scans it again as an "after" visit. The second scan comes from a simulated phone with noise and drift. Every pixel of the "after" scan knows which object it shows and whether that object changed, so any change detector can be scored exactly. The pictures below are one real scenario (held-out seed, kind mixed) rendered by scene_change/harness.

The pipeline

Each step is a function in scene_change/harness/; one seed gives the same scenario every time.

Build the apartment

Five rooms (living, kitchen, hallway, bedroom, bathroom) with walls, doors, furniture, small items and wall items. Everything is axis-aligned coloured boxes, about 95 objects.

Plan the walks

A baseline walk and a later inspection walk through every room: walking segments plus slow pans at each stop, like a person filming with a phone.

Change the scene

Eight changes per mixed scenario: 2 removed, 2 added, 2 moved, 2 appearance. The inspection visit also gets different lighting (exposure, white balance, lamps).

Ray-cast RGB-D

BoxRenderer casts a ray per pixel at 160×120 and returns colour, metric depth and the id of the object hit. Shading uses ambient, ceiling and lamp terms.

Add sensor realism

Depth noise σ = 0.0015 + 0.0025·z² m, 1% dropout, flying pixels at depth edges, RGB noise, exposure jitter, and drifting device poses (VIO drift).

Write ground truth

Per-frame change masks from the object-id maps (which pixels show a changed object), the change list, and the true poses. Detectors only ever see the noisy capture.

Anatomy of one frame

The eight changes

For each change: the baseline scene rendered from the inspection pose, the noisy inspection frame, and the ground-truth mask. "Seen in" counts the inspection frames where it covers enough pixels to be judged.

Stressors: the same frame, degraded

The robustness study re-runs every detector on these degraded captures and finds where each one breaks. Image stressors hit every method; depth noise only hits methods that use depth. Coverage, fewer views and map compression act on whole walks or maps, so they have no single picture.
